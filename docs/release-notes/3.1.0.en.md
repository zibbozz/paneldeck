Paneldeck 3.1.0 brings **syntax colours** to the editor and makes chats with local models much more capable. The editor's new **Syntax mode** colours Rust, Python, TypeScript/JavaScript, C#, C/C++, Go, PHP, SQL, PowerShell, AutoIt, Inno Setup, Visual Basic and many more languages; new files stay in Text mode until you switch it on. Local chats can now run **commands in the background**, **ask you questions with choices**, read **images and screenshots**, work in a read-only **plan mode** with selectable detail levels, and **compact** long conversations so they fit into the model's context. A security fix makes sure a permanent *Always* approval no longer matches commands with command substitution. Settings, chats, sessions and the agent interface stay compatible.

> Independent open-source project – not affiliated with, endorsed by or reviewed by Anthropic.
> The installer and `paneldeck.exe` are **not code-signed** yet, so Windows SmartScreen may warn on first start ("More info" → "Run anyway"). The macOS version is experimental and not signed or notarized. See the README for details.

### Added

- Editor: **Syntax mode** with syntax colours for Rust, Python, TypeScript/JavaScript, HTML/CSS/JSON, C#, C/C++, Java, PHP, AutoIt, Batch, CMake, Go, Inno Setup, XML, LaTeX/TeX, Lua, Makefile, NSIS, Pascal/Delphi, Perl, PowerShell, Ruby, Shell, SQL, Visual Basic (VB.NET, VBA, VBScript), YAML, INI, Markdown, TOML, Dockerfile and every other grammar of bat. The language is detected from your own mappings, the file name/extension, a shebang or a modeline and can be changed per file in the status bar; the mode (Text / Syntax) is chosen per file, per language or for all files. **New files stay in Text mode** until you switch Syntax on. Colours come from the theme (new colours `code_*`), only visible lines are coloured and edits recolour from the changed line on; large files stay plain. New optional `settings.json` fields `editor.default_mode`, `editor.language_modes` and `editor.language_map` (#312)
- Local chats: **background commands**. `run_command` with `background: true` returns an id (`bg1`, `bg2` …) at once and runs the command in its own visible terminal below the chat; new agent tools `command_status`, `command_output` (the last lines, `tail` or pages with `offset`/`limit`, also while it runs) and `stop_command` (Ctrl+C, then the terminal is closed). When a background command ends, a message from Paneldeck appears in the chat, and the model continues if its round is still running. At most 3 background commands per chat run at the same time – adjustable under *Settings → Models → Agent tools* (1–10); new optional `settings.json` field `agent_tools.background_limit` (#355)
- Local chats: `run_command` can pick one of your **profiles or shells** with `shell` (e.g. Git Bash or WSL; default is the project's profile). Administrator profiles and profiles with their own program, arguments or startup command are never used (#355)
- Local chats: new agent tool `ask_user` – the model can ask up to 4 **questions with choices** (2–6 options each, single or multiple choice, always *Other …* with free text) in one small form with *Submit*; options the model recommends come first and are marked *(Recommended)*. *Cancel* tells the model you do not want to answer. While the questions are open, the chat shows *waiting for you* and asks for attention like an approval (#356)
- Local chats: **images and screenshots** in the input – paste with Ctrl+V on Windows (also screenshots taken with Win+Shift+S), pick files with the new paperclip button or drop image files from Explorer onto the chat. The input shows `[Image#1]` at the cursor; clicking the token (in the input and in sent messages) opens the image in a popup (Esc closes). Models that can read images get them (Ollama: detected from the model's capabilities; OpenAI-compatible servers: tried, and a clear rejection is remembered for the model unless it is known to read images). Images larger than 1568 px or 5 MB are scaled down for the model, the original stays. For models without image support the image stays in the chat but is not sent, and a note names suitable models. For models with image support, `screenshot` and `read_file` (image files in the project folder) return the image itself. Images are stored in `chats/<id>/images/`, deleted with the chat and listed in *Clean up* (*Chat images*); new optional fields `images` in `chats/<id>.json`, `vision` per model and per reported model in `settings.json`, new setting *Images* (Auto/On/Off) per model in *Settings → Models* (#357)
- Local chats: **compaction** – *Compact* in the chat header or `/compact` lets the chat's model summarise the older messages; the summary replaces them in the requests, while the system prompt, the last two rounds, open to-dos and the touched files stay word for word. The originals stay in the chat (*Show original*) but are no longer sent. A safety window of max(4096, 15 % of the context) tokens keeps the summary request always within the context; tool results are shortened for it. Optional automatic mode before a request from 80 % of the room (*Settings → Models → Compacting chats*, off by default); if compaction fails, the chat stays unchanged. New optional `settings.json` object `chat_compact` and chat-file fields `compacted`/`summary`; `read_chat` marks both, and `send_chat_message` with `/compact` compacts (`compacting: true`, error code `compact_failed`) (#359)
- **Plan mode** for local chats: a **Plan** toggle next to *Send* (Shift+Tab in the input) with the levels *low*, *medium*, *high*, *xhigh* and *max* applies to the next message. The model first researches with read-only tools only – Paneldeck refuses every writing call with the error `plan_mode` – and then writes a plan; each level has fixed instructions for structure, depth and a research budget (from 5 tool calls at *low* to no limit at *max*), and from *high* on the model clarifies open points with choice questions first (mandatory at *max*). The plan appears as a **plan card** with *Execute*, *Request changes* (with a comment), *Discard* and *Export*; only *Execute* unlocks the writing tools, fills the chat's to-do list with the plan's steps and saves the plan as Markdown in the data folder (`plans/`). While plan mode is on or a plan waits for a decision, `send_chat_message` of external agents is refused with the new error code `plan_pending`. New optional field `plan` in `chats/<id>.json` (#358)

### Changed

- Local chats: the foreground time limit of `run_command` (`timeout_secs`) now goes up to 30 minutes (before: 10 minutes); default (2 minutes) and maximum are set under *Settings → Models → Agent tools*. A larger value is lowered to the maximum and noted in the result. New optional `settings.json` field `agent_tools.command_timeout_max_secs` (#355)

### Security

- Local chats: a permanent approval *Always for this chat* for commands (e.g. `cargo test`) no longer applies to commands with command substitution or expansions (parentheses, braces, `%`, `!` …) – they always ask. Such rules now also apply only to the same shell and the same mode (foreground or background) (#355)
