Paneldeck 2.2 brings **chats with local models**: a new session type next to terminals that talks to Ollama, LM Studio, the llama.cpp server or vLLM on this computer or in your private network. A model with tool support can use Paneldeck's agent tools from the chat – within a level you choose per model and with an approval for every write action. It is a minor version: settings, sessions, the database and the agent interface (MCP) stay compatible; the new data is described under *Upgrade notes*.

> Independent open-source project – not affiliated with, endorsed by or reviewed by Anthropic.
> The installer and `paneldeck.exe` are **not code-signed** yet, so Windows SmartScreen may warn on first start ("More info" → "Run anyway"). See the README for details.

### Highlights

- **Chats in the Terminal Hub:** start one with the speech-bubble button, *New chat* in the palette or the empty hub, or *New chat here* on a folder, then pick server and model. Chats live in projects, folders and splits, work in further and detached windows and come back after a restart. Answers stream as Markdown with a copy button on code blocks; Stop, regenerate the last answer, edit your last message, Retry after an error, token usage and a note when an answer was cut off at the token limit.
- **Settings → Models:** add Ollama (suggested automatically on `http://localhost:11434`) or OpenAI-compatible servers, fetch the models with *Connect* (tool support and context length for Ollama), and store an optional API key encrypted for your Windows user (DPAPI).
- **Tools with your rules:** a new model starts with tools *Off*; the first chat with it asks once whether it may use Paneldeck (*Off* / *Read* / *Control* – independent of the MCP level for external agents). Per model you can uncheck single tools, decide whether write actions need your approval (on by default) and limit the tool calls per answer (default 10, then *Continue*). The approval shows the full arguments and the target session: *Allow*, *Deny*, or *Always for this chat* for that tool on that session – revocable under *Permanent approvals* in the chat header. Every call shows up as one collapsed line with parameters and result. The tools run inside Paneldeck with the chat as the caller, under the same safety rules as for external agents.
- **Local only:** Paneldeck connects only to this computer and private networks. Public addresses, carrier-grade NAT (`100.64.0.0/10`) and ambiguous numeric forms are rejected, host names are resolved and every address is checked before each request, connections go to the checked address without proxy or redirects, and HTTPS certificates are always verified. No telemetry, nothing goes to a cloud service.
- **Agents and chats:** external agents see chats in `list_sessions` (`kind`, `model`), list servers and models with `list_models`, read chats with `read_chat`, send messages with `send_chat_message` and create chats with `create_session` (`kind: "chat"`). They can never approve a chat's tool calls or answer its level question.
- **Mouse wheel in terminals (#141):** wheel and clicks reach programs in every mouse encoding, full-screen programs without mouse support (`less`, `man`) scroll with the wheel via arrow keys (new setting *Mouse wheel in full-screen programs*), and Shift+wheel always scrolls Paneldeck's scrollback.
- **Fixed:** a maximized window no longer has a transparent gap on all sides (#134).

### Added

- Session type "Chat" with streaming Markdown, copy buttons, Stop, regenerate, edit last message, Retry, tool call lines, a marker from where the model no longer sees older messages, token usage, a cut-off note and a notice for models without tool support.
- *Settings → Models* with servers (Ollama, OpenAI-compatible), *Connect*, encrypted API keys and per-model settings (level, allowed tools, ask before write actions, max steps, tool calling, context length); dialog *New chat* that remembers the last choice.
- Tool loop with approvals: *Allow*, *Always for this chat* (tool + target session, revocable under *Permanent approvals (N)*), *Deny*; the approval shows the full arguments and the target session; *needs you* marker in the sidebar while a call or the level question waits; *Continue* after the maximum number of tool calls (rejected calls count too) and a separate stop when the model keeps calling tools that cannot run.
- Tool results are capped at 16 KB (the end of terminal output is kept, marked as untrusted); when the context is full, older results are elided and the chat pauses with a notice. Screenshots are not passed to chat models. Conservative token estimate, calibrated by the server's real counts; Ollama gets `num_ctx` and `num_predict`.
- MCP: `list_sessions` reports `kind` and `model`; new tools `read_chat` and `list_models` (Read) and `send_chat_message` (Control); `create_session` accepts `kind: "chat"`, `server` and `model`; `wait_for_status` waits for chats too; new error codes `not_a_terminal`, `not_a_chat` and `no_model` (`busy` and `permission_pending` now also apply to chats). Messages sent by an agent are marked "Sent by agent …" in the chat.
- Setting *Settings → Appearance → Mouse wheel in full-screen programs*: *Send arrow keys* (default) or *Off*.
- New data: `chats/<id>.json` (version 1) per chat, with `always_allow`; optional fields `llm_servers` (with `level_chosen` per model), `last_chat_model` and `alt_screen_wheel` in `settings.json`, `kind` and `chat` per session in `state.json`, `how` and `model` in `mcp-log.jsonl`.
- New guide `docs/en/chat.md` / `docs/de/chat.md` – chats with local models (setup, settings, security, limits, troubleshooting).

### Changed

- Closing a chat that has a history asks first (when close confirmation is on), also when a window or a folder with chats is closed; the update dialog counts running chat answers separately.

### Fixed

- A maximized window no longer has a transparent gap on all sides through which the desktop showed (#134).
- Mouse wheel (#141): wheel and clicks are reported in all mouse encodings (SGR, UTF-8, normal – the normal one only up to column/row 94, as ConPTY garbles larger values); in full-screen programs without mouse support the wheel sends arrow keys only if the program allows it (DECSET 1007); Shift+wheel always scrolls Paneldeck's scrollback (full-screen programs have none); after a crashed full-screen program the wheel at the shell prompt sends no arrow keys (needs shell integration).

### Upgrade notes

- **Update from 2.1:** install over the old version or replace `paneldeck.exe` of the portable folder; settings, sessions, the database, prompts and themes are kept. Nothing changes until you set up a server under *Settings → Models*.
- **New data formats:** chat histories are stored in `chats/<id>.json` in the data folder (written atomically; a corrupt file is kept as `.defekt-<time>.json`). `settings.json` gets `llm_servers` and `last_chat_model`, `state.json` marks chats with `kind: "chat"`. All new fields are optional, older files load unchanged. **Closing a chat deletes its history** – use *Save history to file …* to keep a copy.
- **Going back to 2.1:** 2.1 can still read the files. It shows chats as (empty) terminals and leaves `chats/*.json` alone. Once 2.1 saves its files, the chat servers in `settings.json` and the chat marks in `state.json` are gone – a later 2.2 then shows those sessions as terminals; the history files stay in `chats/`.
- **API keys are bound to your Windows user:** after copying the data folder to another user or computer, enter the keys again in *Settings → Models*.
- **Chat tools are independent of the MCP level:** a model's level under *Settings → Models* applies even when *Settings → Agents* is *Off*. A new model starts with *Off* and asks once on its first chat; write actions need approval by default. With level *Control* the tool descriptions take about 4.5k tokens – raise the model's context length (e.g. 16k–32k) if the model and your graphics memory allow it.
- **Unsigned builds and antivirus:** the releases are still not code-signed. Microsoft Defender and other antivirus programs occasionally flag unsigned builds as malware (a false positive). Each release is scanned with Defender before publishing; compare the SHA-256 of your download with `SHA256SUMS.txt`, and see the troubleshooting guide if a scanner complains.
