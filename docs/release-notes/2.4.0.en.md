Paneldeck 2.4.0 brings a **terminal template library**: define a terminal once with all its settings and start it again and again – by double-click, by dragging it onto a folder or a pane, from the palette or via the agent interface (`create_session` with `template`). It also makes the **Claude status reliable**: no more sessions stuck on “working” or “approval?” after an interruption, an error or a crashed Claude, and the queue only continues when Claude really finished an answer. **Deleting folders** in the sidebar works the way you would expect, the **file tree** stays on the session's working folder, and the **Settings window** can be moved. Under the hood the Windows-specific code now sits behind a platform layer and is built and tested on Linux and macOS too – the base for the Linux and macOS releases planned for 2.5.0. Settings, sessions, data and the agent interface stay compatible.

> The installer and `paneldeck.exe` are **not code-signed** yet, so Windows SmartScreen may warn on first start ("More info" → "Run anyway"). See the README for details.

### Added

- Terminal template library: define a terminal once with all its settings (name, profile/shell, start folder incl. WSL paths, tree folder, colour, tags, notes, Claude on/off with start options, conversation and start prompt) and start it as often as you like. Templates live in a collapsible *Templates* section at the bottom of the sidebar, with search; start one by double-click, by dragging it into the session list, onto a folder or onto a pane (split/replace), from its context menu, the command palette or a folder's context menu (*Start template here*). Repeated starts count up: `API`, `API #2`, `API #3`. Create one from a session (context menu *Save as terminal template …*) or from scratch (+), then edit, duplicate or delete it. Group templates (*Save as template …* on a folder) share the same library and now also keep colour, tags, notes and all Claude start options. Before a template starts Claude Code with extra folders, allowed tools, an MCP config, `--safe-mode` or an appended system prompt, Paneldeck lists these values and asks (*Start* / *Start without these options* / *Cancel*); such templates are marked with ⚠ (#244)
- MCP: `create_session` takes an optional `template` (name of a terminal template); the call's parameters override the template, repeated starts count up, and the result has a `template` field. Agent rules apply: administrator profiles are refused, and the template's extra folders, allowed tools, MCP config, `--safe-mode`, `bypassPermissions` and *continue the last conversation* are never used and are listed in the new result field `template_ignored`; templates whose profile runs its own program, arguments or startup command are refused unless it is the project's default profile (#244)
- Plugin folders (`--plugin-dir`) in the Claude options, several MCP configuration files, the switch *Only MCP servers from these files* (`--strict-mcp-config`) and a multi-line *System prompt* (`--system-prompt`, replaces Claude Code's built-in system prompt, with a warning). Only you can set them; sessions created by agents never get them, and templates ask before starting with them; line breaks in the system prompt are kept only in Git Bash, elsewhere they are passed as spaces. Claude is not started when its command line would exceed 8191 characters (cmd limit); the dialogs warn from 8000 (#289)
- The session dialogs have tabs: *General*, *Claude*, *Access*, *Advanced* – in New session, the session settings, the template editor and (Claude, Access, Advanced) in *Settings → Claude → Defaults*. Tabs show how many values differ from your defaults and a dot for warnings or errors; Ctrl+Tab/Ctrl+Shift+Tab and Alt+1…4 switch tabs, Enter creates from any tab, each tab can be reset to the defaults, and a command-line preview can be copied. New session also sets colour, tags and notes (#292)

### Changed

- The Settings window can be moved like a normal window; it opens centred and stays inside the window (#275)
- Deleting folders in the Terminals sidebar: the trash icon on a folder now closes all its sessions (same confirmation listing what ends, including subfolders, minimized sessions and chats) and then deletes the folder with its subfolders; an empty folder is deleted directly. *Delete folder (content stays)* in the context menu, and deleting a project or a template, now ask in a confirmation dialog with the 3-second timer instead of “click twice”. The new menu entry *Delete folder with its sessions …* does what the trash icon does (#276)
- All dialog windows (New session, session settings, template editor, confirmations, worktree dialog, templates, prompt composer, prompt library, notes, queue, changes, cost overview, Claude history, search, Claude files, update dialogs, icon explorer …) can be moved by dragging their title bar like a normal window; they open centred, keep their position while open and always stay inside the window (#288)
- Modal dialogs (ticket, sprint, board, release, dashboard, backup/CSV, keywords, filter, to-do dialogs, quick menu, New chat, link prompt) can be moved by a slim drag strip at the top; they open centred, keep their position while open and always stay inside the window (#288)
- Extra folders, plugin folders and MCP configurations are edited as lists with + (folder or file dialog, WSL paths for WSL sessions) and − (asks before removing) instead of text fields; a single MCP configuration from older versions is taken over (#289)
- The New session dialog and the session settings no longer grow off the screen: fixed size with tabs, scrolling only on very small screens; notes grow up to four lines while you type (#292)

### Fixed

- When a folder is deleted while keeping its content, its defaults for new sessions (working folder, profile) pass to its direct subfolders; deleting a folder with its sessions leaves no entries of it behind (#276)
- The file tree (Ctrl+Shift+O) always uses the session's working folder as its root instead of following the shell (or Claude) into subfolders; the shell's current folder is expanded and highlighted inside the tree, also for WSL sessions; network and WSL folders are read in the background (#277)
- A Claude session no longer stays on “working” when Claude Code does not report the end of a turn: after an interruption with Esc, an API error or a reached usage limit the status turns to “ready” within a few seconds (Paneldeck reads from the transcript how the turn ended). If nothing shows how it ended, the status is cleared after 20 seconds without any sign of work (5 seconds after you typed into the terminal) (#282)
- The queue only continues by itself after Claude finished answering a prompt: not after an interruption or an error, not after `/clear`, and not for a Claude started by hand in the same terminal (until *Resume* or Reload); when Claude ends while prompts are queued, the queue is paused with a notice. A prompt is no longer taken out of the queue when the shell has already exited, and a Stop message delivered twice no longer sends two prompts (#282)
- “approval?” stays as long as the question is open – it no longer switches to “working” because another tool or sub-agent running at the same time reported something. After you answered in the terminal it no longer stays either: a denied approval becomes “ready”, an approved long-running tool “working” (#282)
- A sub-agent that keeps running in the background after Claude's answer no longer leaves the session on “working” for good, and automatic compaction in the middle of a turn no longer shows “ready” (which sent the next queued prompt into the running work); `/compact` shows “working” while it runs (#282)
- When Claude ends without reporting it (killed, crashed), the status disappears once the shell shows its prompt again and nothing else runs in it, and a Claude started again in the same terminal is tracked again – in PowerShell, cmd and Git Bash with the shell integration; in WSL only “working”/“ready” is cleared (Reload tracks a restarted Claude again). Program output that imitates a shell prompt cannot end an open approval or take over the session's conversation (#282)
- A status Paneldeck only assumed – a prompt sent by the queue or an agent that started no turn (e.g. `/model`), a cancelled `/compact` – falls back to “ready” after 10 seconds instead of staying on “working” (#282)
- Notifications that ask nothing of you (e.g. after signing in) no longer set the status to “input”; with older Claude Code versions approval and idle notifications are recognised by their text (#282)
- Global hooks: with `CLAUDE_CONFIG_DIR` set, Paneldeck installs, detects and removes its hooks in that folder; hooks installed by an older version keep working (sessions additionally get the hooks via `--settings` until you reinstall them); removing the hooks no longer rewrites a settings file that contains none of Paneldeck's; sessions whose profile sets its own `CLAUDE_CONFIG_DIR` get the hooks via `--settings` (#282)
