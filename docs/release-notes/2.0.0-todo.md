### Bekannte Lücken (bewusst offen, vor dem Release entscheiden)
- Die Tabelle der Suchergebnisse hat keine Chip-Spalte (Version/Meilenstein/Terminal) und scrollt nicht zum geöffneten Ticket (nur die Ticket-Liste tut das).

- Ein Agent kann `session:N` in ein Terminal-Feld schreiben (auch eine fremde oder nicht vorhandene Sitzung); die Oberfläche zeigt sie dann als beendet bzw. springt nicht.
- Ein sehr großer Import (bis 128 MB) blockiert die Oberfläche, solange er läuft.

## 4. Hinweise zu dem, was bewusst anders formuliert ist
- Der Reiter heißt in der Oberfläche **„Todo-Liste“ / „Todo list“** (nicht „Aufgaben“); die Dokumente verwenden diesen Namen.
- Die Standard-Typen heißen englisch *Epic, User story, Dev task, Subtask, Defect*, deutsch *Epic, Userstory, Dev-Aufgabe, Unteraufgabe, Fehler* (aus `planning/defaults.rs` und `names.rs`).
- Reiter eines Projekts: Tickets, Übersicht, Suche, Boards, Backlog und Releases (nur wenn das Projekt Sprints bzw. Versionen nutzt), Dashboards, Typen, Felder, Status, Workflows, Schnellaktionen, Verknüpfungstypen, Arten der Arbeit, Vorlagen & Sicherung (`tabs()` in `src/app/planning_ui/mod.rs`).
- Das Terminal-Feld im Ticket zeigt die Sitzung an; ein Klick auf einen laufenden Eintrag springt zur Sitzung im Terminal Hub. Der Chip im Terminal Hub öffnet umgekehrt das Ticket.
