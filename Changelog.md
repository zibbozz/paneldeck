# Changelog

All notable changes to this project are documented in this file.
A German version of this changelog is in [`Changelog.de.md`](Changelog.de.md).

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Deviation: instead of `[Unreleased]`, changes that are not yet released are listed under the number of the next release with `WIP` instead of a date (e.g. `## [1.1.0] - WIP`).

## [2.1.0] - WIP

### Added

- **System prompt for agents (#61):** when an agent connects over MCP, Paneldeck sends it a detailed guide in the `initialize` reply (field `instructions`): what Paneldeck is, the permission levels, calling `whoami` first, the safety rules, terminal content as untrusted data, simple vs. expert mode, the limits of `run_command` and the error codes. The tool list contains only the tools usable at the current level and mode. Meant for local models and other programs that don't know Paneldeck; English or German (new optional setting `mcp_prompt_lang` in `settings.json`, default English, independent of the UI language).
- **Settings → Agents → System prompt:** choose the prompt language; edit the template, saved as `system-prompt.md` in the data folder (at most 64 KB; "Reset to default" keeps the old one as `system-prompt.md.bak`); placeholders `{{tools}}`, `{{level}}`, `{{mode}}` and `{{version}}` with a legend and a warning for unknown ones; rendered preview, "Copy" and "Save as file…" (.md).
- **Command-line options (#60):** `--data-dir <folder>`, `--profile <name>`, `--backup-dir <folder>`, `--lang en|de`, `--no-tray`, `--reset-settings`, `--version` and `--help` (`-h`, `-?`; explains every option with examples). The data folder is looked up in this order: `--data-dir`, environment variable `PANELDECK_DATA`, the portable `paneldeck-data` next to the exe, `%APPDATA%\Paneldeck`. Profiles (`<data folder>\profiles\<name>`) run as separate instances side by side, because the single-instance lock is per data folder. `--lang`, `--backup-dir` and `--no-tray` apply only to that start and are never saved; `--reset-settings` keeps the old settings as `settings.json.bak-<time>`. Output goes to the calling console, otherwise to a window; invalid arguments end with exit code 2, an unusable folder with exit code 1. A single folder passed without an option (e.g. dropped onto `paneldeck.exe`) opens like `--open`; a file opens its folder.
- `paneldeck.exe mcp` accepts `--data-dir`, `--profile` and `--lang`. Started from a Paneldeck terminal, the bridge automatically connects to the hub of that terminal (also for profiles).
- *Settings → About* and the diagnostics show where the data folder comes from (parameter, environment variable, portable, `%APPDATA%`), the profile and the active start options.
- Instances started with their own data folder (`--data-dir`) or profile (`--profile`) carry these parameters into the integrations they set up: autostart (own Run value `Paneldeck (<profile>)`), Explorer context menu and Claude Code registration (own server name `paneldeck-<profile>`, e.g. `claude mcp add --scope user paneldeck-work -- "<exe>" mcp --profile work`). An instance with only its own data folder uses a short, stable hash of the folder in these names; profile names are case-insensitive. *Settings → Agents* shows the server name of the instance. The entries of the default instance are unchanged.

### Changed

- The `instructions` text in the MCP `initialize` reply is now this system prompt instead of the previous short fixed text. A too large, invalid or empty `system-prompt.md` falls back to the built-in template. `initialize` and `tools/list` wait at most about 1.5 s for Paneldeck's current level and mode.
- Unknown options or extra arguments on the command line are now reported as an error (exit code 2) instead of being ignored silently. Options that only affect the start of an instance (`--lang`, `--backup-dir`, `--no-tray`, `--reset-settings`) are not handed over to an instance that is already running.
- The MCP error `hub_not_running` names the data folder that was searched.
- *Settings → Windows integration* shows whether autostart and the context menu belong to this instance, to another Paneldeck (its command in the tooltip) or are off. The context menu exists once; the instance that switches it on last is the one it starts. Registry entries are written through the Windows API instead of `reg.exe`.
- Uninstalling removes all Claude Code MCP registrations of this Paneldeck (`paneldeck` and `paneldeck-*` pointing to the installed program; others are left alone), even when `claude` is not on the PATH, and the autostart entries of profile instances. The rest of `.claude.json` stays byte-identical, `CLAUDE_CONFIG_DIR` is honoured, and the uninstaller no longer waits indefinitely for `claude mcp remove` (20 s limit).

## [2.0.0] - 2026-11-15

Next to the Terminal Hub, Paneldeck gets a second main area: a to-do list that grows into a small ticket system (projects, ticket types, fields, workflows, boards) with "Expert mode". A new main area counts as a MAJOR version; the existing functions, settings and data stay compatible: the MCP interface only gains new tools (none changed or removed), the command line is unchanged, and the database `paneldeck.db` is new (see "Changed").

### Added

- **New title bar with tabs:** Paneldeck now draws its own title bar (frameless window) with the tabs **Terminal Hub** (the previous view, unchanged) and **Todo list** (new); minimize, maximize and close sit on the right. Switch with a click, `Ctrl+1` / `Ctrl+2` or `Alt+Shift+1` / `Alt+Shift+2` (editable under *Settings → Shortcuts*). Dragging, double-clicking to maximize and resizing at the edges work as usual; on Windows 11 the window has rounded corners and the Snap Layouts menu at the maximize button. Paneldeck always starts in the Terminal Hub.
- **Local database and automatic backups:** the new areas store their data in an SQLite file `paneldeck.db` in the data folder. Before every schema update (migration) Paneldeck automatically makes a backup; a database written by a newer Paneldeck version is left untouched (with a message). New settings tab **Data & backup**: automatic backup (default: every 24 hours, two copies; if the computer was off when a backup was due, it is made at the next start, and several missed backups result in only one), a freely chosen backup folder with "Open folder", "Back up now" (does not count against the number of copies), a list of all backups with date, kind and size, and **Restore** (the current state is backed up first, then Paneldeck quits and restores the backup at the next start).
- **Simple to-do list** (Expert mode off): cards with an optional title (bold) and optional text – at least one of the two –, a quick entry line (Enter creates a card) and an expandable form (`Ctrl+Enter`), check boxes to complete cards (completed = struck through and slightly transparent), editing cards afterwards, ordering by drag & drop, `Ctrl+N` for a new card. Permanently deleting a card (trash can) or all completed cards asks for confirmation with a 3-second safety timer. Completed cards can be hidden and shown.
- **Tags and filters in the to-do list:** tags are created automatically while you type (like labels in Jira) and get a color; the tag manager can rename, recolor, merge and delete tags; you can filter by tags (all selected tags must match) and by open/completed.
- **Undo and redo** for the to-do list (`Ctrl+Z`, `Ctrl+Y` or `Ctrl+Shift+Z`); how many steps are kept (3, 5, 10, 25, 50 or 100; default 25) is set under *Settings → Data & backup*. Deleting stays permanent.
- **Expert mode** (switch in the header of the *Todo list* tab, off by default, the state is remembered): the list turns into project management modeled on Jira. The simple to-do list then appears as the read-only system project `TODO` (key `TODO-12`).
- **Projects** with a key (2–10 characters, e.g. `PAN`), name, description, working folder (repo path) and color; the project color is the accent color throughout the *Todo list* tab (including the active tab in the title bar). A "New project" wizard with the choice of whether to create the default types including workflows, sprints and versions/milestones that can be switched on per project, a color mode for new tags (default, project color, random); project overview, settings and deletion with a safety timer.
- **Freely configurable ticket types, fields, statuses and workflows:** the default types are *Epic*, *User story*, *Dev task*, *Subtask* and *Defect* (in German Epic, Userstory, Dev-Aufgabe, Unteraufgabe, Fehler) with color and icon; hierarchy rules define which type may sit below which. Per type there is an editor for fields (text, rich text as Markdown, checkbox, dropdown with colored values, number with limits and unit, ticket link, terminal, version, milestone, date, date and time, multi-select/labels – with required field, default value, help text, section, order and "show on card"), a status pool per project (name, color, category To do / In progress / Done) and per type a **workflow** with a transition matrix plus required fields, conditions and automatically set values per transition. Types without a workflow have no status field. Default names (types, statuses, fields, priorities, link types, kinds of work) follow the language setting until you rename them. Deleting something that is still in use requires choosing a replacement or deliberately discarding the usages (with a counter).
- **Link types and kinds of work:** *blocks / is blocked by*, *relates to* and *duplicates / is duplicated by* are built in; you can create your own link types with a ticket, terminal, URL or git branch as the target. The **Terminal** type is a system type and cannot be deleted. The kinds of work for time tracking (default: Development, Testing, Planning, Refinement) can be set per project.
- **Templates:** the types, fields, statuses and workflows of a project can be exported as a JSON file and imported into another project; the import only creates what is missing and reports items with the same name without changing existing ones.
- **Tickets:** keys made of the project key and a running number (`PAN-12`, never reused), fields per type, parent and children with progress, flag and favorite (star), comments, links, time tracking (input like `1h 30m` or `2d`; a number alone counts as hours) and a change history that records whether the window, an agent (with session name) or an import changed something. Status changes check the workflow (transition matrix, conditions, required fields) the same way everywhere: in the window and for agents.
- **Kanban boards** in Expert mode: several boards per project with name, description, columns (also several statuses in one column), a type filter and freely chosen card fields. Cards can be dragged between columns (that is a status change with all workflow rules; if required fields are missing, a dialog opens) and reordered within a column; quick filters by text, type, favorites and flag. The source of a board is "All tickets" or a saved filter (also across projects), and "Only the active sprint" shows only the tickets of the active sprint. Moving, reordering, starring and flagging a card can be undone and redone with `Ctrl+Z` / `Ctrl+Y`. Cards also show the fields *Version*, *Milestone* and *Terminal* (ended sessions in gray).
- **Tickets in the window:** a *Tickets* tab with a list (columns key, title, type, status, priority, points; sortable, text search, filters by type and status, favorites only, flagged only), a create dialog (choose the type, parent ticket, "Create another"; `Ctrl+N`), a detail view as its own page or as a side panel next to the list (switchable, the choice is remembered), fields per type in sections with a required-field check, status changes only via allowed transitions (missing required fields are asked for in the same dialog), comments (edit, delete), links and child tickets, change history, undo/redo with `Ctrl+Z` / `Ctrl+Y`, clone (one check box per field), change the type or move to another project (with a list of the fields that are kept, dropped and added), flag and star, "Log time" (duration, kind of work, start, comment) and turning a to-do card into a ticket (one undo step: the ticket goes away and the card is open again; `Ctrl+Z` / `Ctrl+Y` also work in the Todolist overview). From a width of 900 px the list also shows a chip column with version, milestone and terminal; it scrolls to the opened or just closed ticket when its row is not fully visible. A terminal entry in the ticket jumps to the running session. Permanently deleting a ticket asks for confirmation with a 3-second safety timer. If you open a ticket from another tab (board, search, backlog, dashboard, overview) or from the Terminal Hub, "Back" (`Esc`) takes you there again.
- **Rich text fields with a "Text | Visual" switch:** Markdown with a formatting toolbar (headings, bold, italic, lists, task lists, quotes, code, tables), rendered only in Visual mode; ticket keys in the text (`PAN-12`) are clickable and open the ticket. No files or images are stored.
- **Query language** (modeled on JQL) for the ticket search: comparisons (`=`, `!=`, `~`, `!~`, `<`, `>`, `<=`, `>=`, `IN`, `NOT IN`, `IS EMPTY`), `AND`, `OR`, `NOT` and parentheses, `ORDER BY` / `SORT BY` with several fields, free text, the functions `activeSprint()`, `currentDate()` and `linkedTerminal()`, the fields `sprint` and `Release version` and your own keywords (`IS favorite`, `IS NOT blocked`, `SORT BY favorites`, defined in the keyword editor). The query bar has autocomplete (`↑↓`, `Tab`/`Enter`), a history of the last queries, error messages with position and suggestion ("did you mean …?") in English and German, and **saved filters** (per project or for all projects; also as the source of a board). It sits above the ticket list (a valid query replaces the local filters there) and in the new **Search** tab, which shows the results as a table (either only this project or all projects). A question-mark button opens a **help page** with a complete guide and examples.
- **Backlog, sprints, versions and milestones** (can be switched on per project, nothing is forced on you): a **Backlog** tab with one active sprint per project (goal, start, end, duration template, work days and holidays), tickets moved by drag & drop (several with `Ctrl`/`Shift`+click) between the backlog and sprints, totals by count or points, starting and completing a sprint (open tickets go back to the backlog or into the next sprint), burndown with ideal line and work days, sprint report and velocity across completed sprints (a sprint lasts at most 4000 days); a **Releases** tab with versions and milestones (due date, "released"/"reached", progress, order, replacement when deleting). Fields of type *Version* and *Milestone* have picker editors in the ticket. Dragging and "Move to" in the backlog can be undone and redone with `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` (not: starting, completing or deleting a sprint, or the actions in the *Releases* tab).
- **Quick actions and the quick menu:** per ticket type you can define buttons with their own name in the **Quick actions** tab (e.g. "Create Devtask"): create a ticket with preset values (optionally linked to the source ticket, with placeholders in texts), change the status (optionally with values) or start a terminal/Claude session for the ticket. The **quick menu** (key `.`, e.g. in the ticket, in the list, on the board and in the backlog) searches fields and actions, sets values directly, changes the status (only allowed transitions; if required fields are open, a small form asks for them) and runs the quick actions. The quick actions "Change status" and "Create ticket" also ask for missing required fields in such a form. In open pick lists of the quick menu, `Esc` only closes the list and `Enter` takes the entry. The quick actions of the ticket type are also available as **buttons right in the ticket** (page and side panel, below the status, in the order of the type editor; with many actions a "⋯ more" menu takes the rest): a click runs the action through the same quick menu (required-field form or title input when needed; a toast with "Undo"; session start), and invalid or blocked actions are grayed out and explain themselves in their tooltip.
- **Dashboards:** a **Dashboards** tab with freely arranged tiles on a grid (search, active sprint, burndown, counts by status/type/priority as a pie or bar chart, booked time per day or week, favorites, flagged tickets, all projects), per project or global; several dashboards with one default, an edit mode (move, resize, "Tidy up"), a click on a row opens the ticket, a click on a chart segment opens the search, export/import as JSON (the import always creates a new dashboard).
- **Export and import:** in the *Templates & backup* tab a full project backup (JSON: types, fields, workflows, boards, filters, tickets with comments, history, links and times, sprints, versions and milestones) and tickets as CSV (optionally "Excel-safe", formulas are protected – also for cells that start with a tab or carriage return) as well as the type/field templates; the import only accepts its own export format, always creates a new project (asking for a new key if the key is taken) and never changes existing data. Files over 128 MB as well as counters, numbers and ranks close to the end of the number range (`i64::MAX`) and sprint periods over 4000 days are rejected before anything is created.
- **Terminal links:** in the Terminal Hub (only with Expert mode on and at least one project) a link icon in the header of a terminal (also via the context menu entry "Link ticket …" of the terminal header and the sidebar) opens a mini search by ticket key or title (`pan-12`, `login`). The ticket key appears as a chip in the terminal header and in the sidebar (with a counter for several tickets); the command palette (`Ctrl+Shift+P`) also finds tickets. When the session is closed, the link stays as "ended" (gray) and becomes active again when the session is resumed. A click on the chip opens the ticket in the *Todo list* tab (Expert mode is switched on for this if needed); "Back" or `Esc` then returns to the Terminal Hub. Fields of type *Terminal* pick a session from a list; in the ticket a click on a running entry jumps to the session in the Terminal Hub.
- **Toasts:** short messages at the bottom right, up to five stacked, each visible for ten seconds, a click closes them. When an agent changes a ticket or a to-do card, a line appears with what it did.
- **Agent interface (MCP): 18 new tools** (33 in total), depending on the mode of the *Todo list* tab – the agent always has only the possibilities of the current mode. In every mode: `list_todos` (read). Expert mode off: `add_todo`, `set_todo_done` (control). Expert mode on: `list_projects`, `get_project`, `search_tickets`, `get_ticket`, `get_time_entries`, `list_sprints`, `get_sprint`, `list_versions` (read) as well as `create_ticket`, `update_ticket`, `transition_ticket`, `add_comment`, `log_time`, `link_ticket`, `link_terminal` (control). Instead of the simple filters, `search_tickets` also takes a query in the query language (`query`, read only; an invalid query returns `invalid_query` with position and message, a text that is too long `too_large`, and after 2 seconds `timeout`); `list_sprints`, `get_sprint` and `list_versions` return sprints (with totals and report) as well as versions and milestones with progress, and answer with `feature_disabled` when the project switch is off. The same rules apply as in the window (required fields, hierarchy, workflow); agents can never delete tickets or cards or change types, workflows and projects. If an agent calls a tool of the other mode, Paneldeck answers with the new error code `wrong_mode` and an explanation. In *Settings → Agents* a line shows which tool group currently applies.

### Changed

- The main window is now frameless with its own title bar (see above); the Terminal Hub view below it is unchanged.
- New data structure in the data folder: `paneldeck.db` (SQLite, schema version 7) with the side files `paneldeck.db-wal` and `paneldeck.db-shm` while running and the folder `backups/` (or the chosen backup folder). Existing files (`settings.json`, `state.json`, `prompts.json`, `themes/`) keep their format; `settings.json` gains the new values `backup_interval_hours`, `backup_keep`, `backup_dir` and `undo_steps` (older files load with the defaults). An older Paneldeck version cannot open `paneldeck.db` – back up the data folder before going back to 1.x.
- The request limit of the agent interface rises from 64 KB to 512 KB (a comment with 20,000 characters can be 80 KB in UTF-8). The hub now answers larger requests with the error code `too_large` instead of silently closing the connection. The response of `list_sessions` gains the additional field `note`, which marks names, folders and branches as untrusted.

## [1.0.1] - 2026-11-14

### Changed

- The installer offers a language choice (English/German) at startup; the names of the components, the entries in the Explorer context menu and the uninstall shortcut follow the chosen language.
- All texts of the agent interface (error messages and notes; error codes and field names stay unchanged), status messages, diagnostic info, default prompts and messages of the git functions are now English by default; German appears when the language in the settings is set to German.

### Fixed

- On systems with a language other than German or English, the installer now falls back to English instead of German.

## [1.0.0] - 2026-11-14

First public release. From here on, the public API (MCP interface, command line, data formats in the data folder) is binding in the sense of Semantic Versioning; earlier development states were not published.

### Added

- **Terminals** with full emulation via ConPTY: PowerShell 7, Windows PowerShell, CMD, Git Bash and WSL distributions; colors, alt screen, mouse, Unicode, color emoji, CJK and seamless box-drawing characters.
- **Organization:** sessions in projects with their own layout, groups/folders (tree view), colors, tags, filters and notes; freely splittable panes, drag & drop (including folders), detach into their own windows, git worktrees per session.
- **Claude mode** (can be turned off): status display via hooks (working / approval? / ready), notifications, token and cost estimates with a cost overview, daily and per-session budget, history with exact resume, start dialog (model, permission mode), editor for `CLAUDE.md` and Claude settings.
- **Convenience:** command palette, history search, prompt library, broadcast to several terminals, file tree, git info, pasting files and images from the clipboard, tray, transparency, Windows notifications.
- **Agent interface (MCP)** with 15 tools (`whoami`, `list_sessions`, `read_terminal`, `screenshot`, `get_usage`, `search_history`, `create_session`, `send_text`, `send_keys`, `run_command`, `wait_for_status`, `queue_prompt`, `rename_session`, `focus_session`, `close_session`): off by default, levels "Read only" and "Control", access check in the hub, call log; agents identify themselves via `whoami` and create child sessions under their own.
- **Customization:** keyboard shortcuts, custom themes (JSON), terminal font, English (default) and German.
- **Windows integration without administrator rights:** installer (per user, with license page) and portable ZIP; Explorer context menu, optional autostart, single instance; uninstalling removes the hooks and the MCP registration again. Updating over a running hub is possible.
- MIT license (`LICENSE`); the license texts of the dependencies ship with the installer and the ZIP (`THIRD_PARTY_LICENSES.txt`).

### Security

- Paneldeck makes no connections to the internet and sends no telemetry; hook and MCP traffic stays local (`127.0.0.1`, with a token).
- All `unwrap()`/`expect()` calls in the program code were replaced by error handling (the release build aborts completely on a panic); the `unsafe` blocks are justified.
- The executable contains no paths of the build machine.
