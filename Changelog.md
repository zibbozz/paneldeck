# Changelog

All notable changes to this project are documented in this file.
A German version of this changelog is in [`Changelog.de.md`](Changelog.de.md).

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Deviation: instead of `[Unreleased]`, changes that are not yet released are listed under the number of the next release with `WIP` instead of a date (e.g. `## [1.1.0] - WIP`).

## [3.3.0] - WIP

### Added

- Editor: **type directly in the comparison tab** – click into an editable side (a document, not the saved file, a git state or the clipboard) and type, delete, paste, cut and copy a selection, press Enter or Tab, move with the arrow keys, Home/End and Page Up/Down (Shift selects), Ctrl+A selects the side. The text appears at once; the differences are recomputed about 300 ms after the last key. The cursor skips filler lines (a click on one puts it at the end of the line above), typing in a collapsed region expands it. Typing shares the undo history of the document with the block arrows and the normal tab (Ctrl+Z/Y on the focused side); Alt+←/→, Ctrl+S and double-click to open the line in the normal tab work as before. Without a cursor the arrow keys scroll as before; typing into a read-only side shows a hint. One cursor only – multiple cursors in the comparison come later (#391).
- Editor: **multiple cursors like Sublime Text**, each part with its own switch in *Settings → Editor* (all off by default): *Multiple cursors* turns on the shortcuts and commands – **Ctrl+D** adds the next occurrence, **Ctrl+Shift+D** selects all occurrences (in the Editor tab; in the Terminal Hub it still splits right), **Ctrl+U** takes back the last cursor or selection change without touching the text. *Middle mouse button*: dragging selects a column (with word wrap by screen rows; short and empty lines get a cursor at their end) and replaces the cursors, **Ctrl+drag** adds the column, a click places the cursor, **Ctrl+click** adds one. *Alt+click* adds a cursor, Alt+click on a cursor removes it (the last one stays). At most 10 000 cursors ("Only the first 10 000 cursors."). The status bar shows "3 cursors" or "3 selections" instead of line and column (#394).
- Editor: new menu **Selection** in the menu bar (add next occurrence, select all occurrences, undo cursor/selection change, single cursor, select line); all of it also in the command palette. The multi-cursor shortcuts are in *Settings → Shortcuts* and can be changed or removed (#394).
- Editor: **Toggle comment** (**Ctrl+/**, *Edit* menu, command palette) on the lines of every cursor, with the line comment of the file's language (`//`, `#`, `--`, `;`, `%`, `'`, `REM`); greyed out for languages without line comments. A second binding can be set in *Settings → Shortcuts* (on German keyboards `/` is Shift+7) (#394).
- Agent interface: `editor_read` additionally returns the user's cursors and selections (`selections`, 1-based line/column, at most 1000) – only with the new switch *Agents see the selections* (*Settings → Editor → Agents*, off by default); `editor_list` reports the switch in `agents.selections` (#394).
- Editor: **Smart mode** (mode picker in the status bar, per file, per language or as default): a language server adds **completion** and **diagnostics** to the syntax colours. Servers come from PATH (a fresh Windows PATH, resolved to an absolute file, never from the project folder; npm `.cmd` shims run through `cmd`, the rustup proxy and the Microsoft Store Python stub are recognised) or from an own path per language – built-in list: rust-analyzer, basedpyright/pyright/pylsp, typescript-language-server, clangd, gopls, lua-language-server, csharp-ls, vscode json/html/css, yaml-language-server, taplo, bash-language-server, texlab, phpactor, ruby-lsp, neocmakelsp, marksman, docker-langserver, jdtls, kotlin-language-server, perlnavigator, lemminx, sourcekit-lsp, each switchable per language; PowerShell, NSIS and SQL with an own path only. The project root is detected (Cargo.toml, package.json, pyproject.toml, go.mod, … or `.git`). Limits (configurable): at most 6 servers (the one unused longest ends), completion timeout 5 s, 1000 diagnostics per file, messages up to 64 MB, smart mode up to 5 MB per file (above: Syntax mode with a hint). A crashed server restarts up to 3 times in 3 minutes. Each server runs without a window in its own job object; requests of a server to change files, run commands or open documents are refused (#367).
- Editor: **folder trust** for smart mode – a bar above the text offers *Trust* (the detected project root), *Trust parent folder …* and *Not now*; until then Syntax mode runs. Trusted folders are listed in *Settings → Editor → Smart mode* and can be revoked there (the servers stop at once); agents can never change them (#367).
- Editor: **completion** opens after the server's trigger characters and after 2 typed word characters (~100 ms pause, switchable) and with **Ctrl+Space**; up to 12 rows with kind, name and detail, documentation beside the selection, local fuzzy filtering; Tab or Enter accept, Esc closes, arrow keys select; snippets with tab stops (Tab jumps, Esc ends) as one undo step (#367).
- Editor: **diagnostics** as squiggles in theme colours (hints dotted, deprecated struck through), the message on hover and for the cursor line in the status bar; error/warning counter in the status bar, **problem list** at the bottom of the Editor tab (counter or **Ctrl+Shift+M**), **F8/Shift+F8** for the next/previous problem. Diagnostics are shown about 500 ms after the last change; stale ones are dropped. Not in the comparison tab (#367).
- Editor: window **Language servers** (status bar, click on the server): language, folder, status, PID, *Restart*, *Stop* and the server's log (in memory only, at most 1 MB; message trace switchable, off by default) (#367).
- Themes: new colours `diag_error`, `diag_warning`, `diag_info`, `diag_hint` for the squiggles (#367).

### Changed

- Editor: the existing multi-cursor features are **off by default** after the update – Alt+click, Ctrl+D and selecting all occurrences only work after switching on *Multiple cursors* or *Alt+click* in *Settings → Editor* (#394).
- Editor: pasting with several cursors always pastes the whole clipboard at every cursor (before, a clipboard with as many lines as cursors was distributed line by line) (#394).
- Editor: Ctrl+D (next occurrence) matches the selected text everywhere, no longer only whole words (#394).

### Removed

- Editor: Alt+Shift+Up/Down (cursor above/below) and column selection with Alt+Shift+drag or Alt+drag – column selection is now done with the middle mouse button; Ctrl+Shift+L (all occurrences) is now Ctrl+Shift+D. Ctrl+Alt+arrow keys still move the focus between splits (#394).

## [3.2.0] - 2026-11-28

### Added

- **Time tab** at the end of the title bar (**Alt+Shift+4**, also in a new window with Ctrl+click) with the sub-tabs Alarms, Timers, Calendar, Stopwatches, Clocks and Birthdays – each a list or view with a detail pane on the right (#164).
- **Alarms:** time plus weekdays or once, name, built-in or own WAV/MP3 sound with preview, snooze (5 min, at most 10 times, changeable per alarm). They ring while Paneldeck runs, also minimized or in the tray; missed alarms (Paneldeck closed, computer asleep) are shown as a hint at the next start ("Missed: alarm 07:00 (Mon)"), also a snooze that ended meanwhile; after the system clock is set back alarms count from the new time. Daylight saving time: a time in the gap rings at the next valid time, the repeated hour rings once (#164).
- **Timers:** several named countdowns at the same time with pause, resume, restart and reset, and saved presets ("Tea 4 min"); they survive restarts and sleep – a timer that ran out meanwhile shows "expired at 14:32" (#164).
- **Calendar:** month, week and day views and a list with details on the right; all-day and multi-day events as bars at the top. Own events with title, time, duration, note, colour, reminder and recurrence. Due dates of tickets and to-do cards, sprints, versions/milestones and booked time can be shown – each switchable in *Options …* for all projects and per project (due dates are on at first open) (#164).
- **Recurring events:** a builder (daily, weekdays, weekly on chosen days, monthly on a day or the n-th weekday, yearly, every X minutes/hours) produces a cron expression that experts can edit directly (5 fields, `@daily` …, `MON#1` for the n-th weekday), with end date or count, single-day exceptions, a preview of the next 5 occurrences and a warning about cron's day-of-month OR day-of-week case. Times are local: a time in the daylight-saving gap moves to the next valid time, the repeated hour fires once (#164).
- **iCal import and export** of local `.ics` files: recurrences are translated to and from `RRULE` as far as possible, the export includes the time zone; the import skips duplicates by UID and broken entries one by one, shows a report and accepts files up to 10 MB (#164).
- **Stopwatches** with laps (start, stop, lap, reset, lap list) that keep running across restarts (#164).
- **World clocks:** city or time zone (IANA database), time, date and offset to local time, digital or analog (#164).
- **Birthdays:** name and date with an optional year; age and countdown such as "37 in 5 days and 2 months", "Today! 🎂" on the day, 29 February shown on 28 February in non-leap years, a reminder per entry (off by default) (#164).
- **Notifications of the Time tab:** sound and toast for alarms and timer ends (on); event reminders of the calendar are off by default (calendar options) and, when switched on, notify the same way – missed ones are shown at the next start; taskbar flashing (off), volume and ring duration – all in *Options* of the Time tab (`settings.json` → `time`); five built-in sounds generated by Paneldeck itself (#164).
- **Time tracking from timers and stopwatches** (off by default): with a ticket set, stopping asks "Book 47 min on PAN-12?" and adds a time entry to the ticket (#164).
- **Tutorial:** new chapter "Time" (tab, sub-tabs, a new alarm, timer presets, calendar views, notification options); its steps also appear in "What's new" (#164).
- **Agent interface:** `list_alarms`, `list_timers`, `list_stopwatches`, `list_clocks`, `list_birthdays`, `list_calendar_events` (Read) and `create_alarm`, `update_alarm`, `create_timer`, `update_timer`, `create_stopwatch`, `control_stopwatch`, `create_calendar_event`, `update_calendar_event` (Control); the list tools are paged (`limit`/`offset`), nothing can be deleted, clocks and birthdays are read-only (#164).
- **Menu bar in every editor split:** *File · Edit · View · Format* above the tab bar, like Notepad++ or Sublime Text – New, Open, Save, Save as, Save all, Close tab; Undo, Redo, clipboard, Find/Replace, Find in files, Go to line and the multi-cursor and line commands; Word wrap, Minimap, Folder tree, Split right/down, Text/Syntax mode and language. Shortcuts are shown on the right, entries that do not apply are greyed out and say why on hover (e.g. *Not JSON or XML*), and in narrow splits the menus fold into one *Menu ▾*. It can be switched off under *Settings → Editor → Menu bar* (on by default). The command palette (Ctrl+Shift+P) now also opens in the Editor tab (#381).
- **Formatting JSON and XML in the editor:** the *Format* menu formats (Alt+Shift+F), minifies (Alt+Shift+M), validates (Alt+Shift+V) and sorts JSON keys – offline, with the indentation from `.editorconfig` or the file, applied directly as **one undo step**, on the selection only if there is one. Invalid content is never changed: a bar shows the error with line and column and a *Go to* button; *Validate* shows "Valid JSON/XML". Formatting runs in the background with a progress line and *Cancel*, so the editor stays responsive – also for large files from 20 MB. Minifying JSONC asks first because it removes the comments. JSON and XML are recognised by extension and well-known names (content only for untitled tabs and files without an extension), and a language chosen in the status bar wins. The shortcuts can be changed under *Settings → Shortcuts* (they avoid Ctrl+Alt, which is AltGr on many keyboards; Ctrl+Shift+I is a second binding for formatting in case Alt+Shift switches the input language), and the commands are in the command palette as *Format: …* (#381).
- **Formatting only when you ask:** nothing is ever formatted automatically. It happens through the *Format* menu, the shortcuts or the command palette – or on save through an *action on save* rule with the *Format (JSON/XML)* action. *Format → Format on save …* opens the rule dialog for the current file with the pattern (e.g. `*.json`) and the action already filled in. Without such a rule, saving writes exactly the text in the editor – also on autosave and when an agent saves. There is no separate setting for it (#381, #383).
- **MCP tool `format_file`** for documents open in the editor: `op` = `validate` (level Read, no switch), `format`, `minify` or `sort_keys` (level Control plus the new switch *Agents may format* in *Settings → Editor → Agents*, off by default). The change stays unsaved, is marked as made by the agent and can be undone; agents never take the keyboard focus. Chats with local models use the same rules while a document is open (the tool is off by default for chats and checked per model under Settings → Models); in plan mode only `validate` runs (#381).
- **JSON and JSONC formatting in the editor:** *Format* pretty-prints with the file's indentation (spaces or tabs), *Minify* removes all whitespace, *Sort JSON keys* sorts object keys recursively (stable, by Unicode code point; array order stays) and formats the result, *Validate* reports the first error with line, column and a clear message (e.g. "expected ',' or '}' after object member") and changes nothing. Values are kept exactly as written: numbers are never rewritten (`1.0`, `1e400`, `0.1000` stay), string escapes stay (`é`), key order and duplicate keys are kept, empty objects and arrays become `{}` / `[]`, one blank line between members is kept, a byte order mark stays. **JSONC** (`.jsonc`, `tsconfig.json`, `.vscode/*.json` or files with comments): `//` and `/* */` comments and trailing commas are kept – a comment on its own line stays on its own line, a comment at the end of a line stays there and moves with its member when sorting, a block comment in front of a member on the same line (`/* about a */ "a": 2`) belongs to that member; *Minify* drops comments and trailing commas. In plain JSON, comments and trailing commas are reported as errors with their position. Works offline; 50 MB files take a few seconds, deeply nested files (10 000 levels) work, indentation stops growing after 100 levels (#381).
- **XML formatting in the editor:** *Format* indents elements gently – comments, CDATA sections, processing instructions, the XML declaration and the DOCTYPE (with internal subset) stay exactly as written, as do elements with mixed content (text next to tags, e.g. XHTML paragraphs), text-only elements, whitespace-only content (e.g. `<xsl:text> </xsl:text>`), inline siblings separated only by spaces (`<b>a</b> <i>b</i>`, in documents with mixed content also `<b>a</b><i>b</i>`) and `xml:space="preserve"` subtrees; tags stay as written (attributes, order, quoting, spacing; continuation lines of a multi-line start tag follow the new indentation of its first line), entity and character references are kept as written, `<a/>` and `<a></a>` keep their form, one blank line between elements is kept, beyond 100 levels the indentation stops growing. *Minify* removes the whitespace between elements and keeps comments. *Validate* checks well-formedness (matching tags, attributes, a single root element, names, unescaped `<` and `&`) and reports line and column; nothing is changed. Works offline: external DTDs and entities are never loaded; large files (50 MB) take about a second (#381).
- Editor: **actions on save** (#383) – rules per file, folder (recursive) or pattern (`.gitignore` syntax, e.g. `src/**/*.ts`, `!dist/**`) in *Settings → Editor → Actions on save*. Before writing: trim trailing whitespace, final newline, line endings, encoding, tabs ↔ spaces, format JSON/XML (the only way a file is formatted on save – nothing is ever formatted automatically; *Format → Format on save …* opens the rule dialog for the current file with the pattern and the action filled in); afterwards in order: run a command (hidden like the process list or visible in a terminal, variables such as `${file}`/`${relativeFile}` quoted for the shell – a variable inside a quoted string is refused –, also as `PANELDECK_FILE` … in the environment, own encrypted environment variables, 60 s time limit with *Cancel*), copy the file to another local folder, send a command to a session waiting at its prompt, restart a process or group, show a notification. The file is always saved; errors show a red dot on the tab, a status bar entry and a notice with *Show output* (last 100 runs, optional rotating log). Autosave and agent saves only trigger when a rule allows it; *Save without actions*, *Pause* until restart and a master switch; *Test for file …*, *Run now*, *Rules for this file* in the folder tree; export/import without secret values (imported rules arrive switched off). Paneldeck itself never accesses the network – uploads only through your own commands. Stored in the new data file `save-actions.json`.
- Agent interface: new tool `list_save_actions` (level Read; names, patterns, action kinds, on/off and last result – never commands or values); `editor_save` reports which rules ran or were skipped (`save_actions`) (#383).
- Editor: file comparison as its own tab (*a.json ↔ b.json*), oriented on Sublime Text/Sublime Merge – compare a file with its saved version, git HEAD, the git index, any revision (HEAD, index, branches, tags, the last 50 commits of the file or a typed revision, checked first), the clipboard or another file; from the tab context menu (*Compare with …*), the folder tree (*Select for compare* / *Compare with …*, or Ctrl+click two files) and the command palette, which now also opens in the Editor tab. Side by side with synchronised scrolling and hatched filler lines (unified automatically below ~700 px, switchable), changes within lines word by word, syntax colours and line numbers on both sides, unchanged regions collapsed with 3 context lines (expandable), block arrows in both directions (one undo step each, in the same document as the normal tab), *Swap sides*, F7/Shift+F7 for the next/previous change (configurable), *Ignore whitespace*, an info bar for differences in line endings, encoding/BOM and the final newline, *Copy diff*, *Copy block*, *Save as patch …* (git-compatible). Updates live while typing; large files are compared in the background with progress and *Cancel*, binary files show size and SHA-256. Comparison tabs are restored after a restart. Everything offline – only the local git (#385)
- Editor: change markers in the gutter (*Settings → Editor*, off by default): added, modified and removed lines against the git index and HEAD at the same time – unstaged and staged changes in their own colours – or against the saved file outside a repository; also in the scrollbar and the minimap. A click on a marker shows the old lines with *Revert* (one undo step), previous/next change and *Open in diff* (#385)
- Themes: new colours for the comparison and the change markers (`diff_add_bg`, `diff_remove_bg`, `diff_add_word`, `diff_remove_word`, `diff_filler`, `marker_*`), with contrast checks, in the theme editor group *Editor: comparison and change markers* (#385)

- Terminals: **environment variables per session** – new tab *Environment* in *New session*, in the session settings and in the template editor: a table with *Name*, *Value*, *Secret*, *Mode* (*Replace*, *Prepend*, *Append* with the platform separator – for `PATH` and other lists), *Remove* (removes an inherited variable) and, for WSL, *Path* (convert via `WSLENV /p`, lists `/l`); up to 100 variables, *Paste KEY=VALUE …* and a one-time *Import from .env …* with a preview and a checkbox per line. **Secret** values are stored encrypted like the process list, masked, never typed, copied, exported or given to agents; the flag is preset for names containing TOKEN, KEY, SECRET, PASS, PWD or AUTH. The pane header shows `$ n` with a tooltip of the names (secret ones as ••••) and an orange dot while a change only applies after a restart. Split and *Duplicate* copy the variables; the sidebar context menu has *Environment variables → Edit …, Copy variables, Paste variables* (secret values never reach the clipboard) and *Copy as .env* (secret values empty, prepend/append as a `# paneldeck: …` comment line that paste and import read back). *Save as terminal template …* takes secret values only when you tick it (#384)

### Security

- Sessions started from an agent chain are now marked (#152): a terminal, Claude session or chat that an agent creates with `create_session` (or `paneldeck --open` from inside a session) inherits the creator's agent chain plus the creator, and a chain member that writes into another session (`send_text`, `send_keys`, `run_command`, `queue_prompt`, `send_chat_message`) passes the chain on. No agent – MCP bridge, Claude session or chat – may write into, rename, focus or close a session of its own chain (`forbidden`). Chains are kept in `state.json` (new optional field `agent_chain`), survive a restart and are reported by `whoami` and `list_sessions`. Agents started by the user behave as before, except that a session an agent creates can no longer write back into its creator.
- The hub now identifies the calling process itself, right when the connection arrives (TCP table, the live process and its process tree with creation times), and ignores a process id supplied by the client; a caller that cannot be identified (already exited, connection gone) is refused. `PANELDECK_SESSION` only counts for WSL terminals and only together with the session's secret key `PANELDECK_SESSION_KEY`. Best effort against a malicious agent with its own shell: processes that cannot be attributed to any session count as external callers; detached or orphaned processes (started after Paneldeck, whose parent has exited) are blocked from writing into sessions that belong to an agent chain and from `--open --claude`; processes started outside Paneldeck entirely (e.g. scheduled tasks, WMI) remain outside the protection.
- WSL start folders containing `"` or `\` are rejected everywhere, so `wsl.exe --cd` cannot be used to inject commands; administrator starts quote every argument correctly. (#172)
- MCP `create_session` refuses network paths as `cwd` for terminals and chats without accessing them; `\\wsl$` paths are no longer probed on the UI thread. (#172)
- OSC 52 is write-only: programs can never read the clipboard. Only the focused session in the foreground window may copy, at most 1 MB, at most once every 0.3 s; empty texts never clear the clipboard. Note: an agent with control access (MCP) can make the focused session copy text, too. (#181)
- Paneldeck no longer loads DLLs from the current working folder: right at startup the DLL search is restricted to the program folder and System32, and the bundled console host is loaded by its full path. (#183)
- The C runtime is now linked into `paneldeck.exe`; it no longer needs `VCRUNTIME140.dll`, which Windows would look for before Paneldeck starts. (#183)
- Agents (MCP) can only add switches that don't affect rights, access or hooks (chrome, no-chrome, ide, verbose, brief, restricted, disable-slash-commands; not chrome if you turned Chrome off by default). Value options, flags that widen rights or access, flags that turn off hooks (`--safe-mode`) and flags Paneldeck controls are refused. Extra folders, allowed tools, an MCP config and `--safe-mode` from your defaults never apply to agent-created sessions or to `paneldeck --open --claude` from a Hub terminal. Paths must be local and existing (network shares, also via links, are never accessed); all values are validated and quoted per shell. (#182)
- Sessions created via MCP without a permission mode get an explicit `--permission-mode default`, so the user's own Claude settings cannot turn on bypassPermissions; `bypassPermissions` is never possible via MCP, never a stored default and never remembered – only an explicit per-session choice with a warning. Old `--dangerously-*` arguments are dropped. (#161)
- Paneldeck starts every terminal's shell inside its own Windows Job Object and attributes MCP callers and `paneldeck --open` by job membership. Processes started detached or orphaned (`Start-Process`, `cmd /c start`, double fork) still belong to their session and its agent chain; programs cannot break away from the job. The process-tree check remains as a fallback. (#168)
- A program pushing thousands of kitty keyboard modes can no longer crash Paneldeck. (#183)
- Pasted text is filtered like Windows Terminal (control characters incl. ESC and C1), so hidden Enter sequences cannot bypass the multi-line warning. (#183)
- Window titles from programs are sanitised (control, bidi, line-separator and zero-width characters, length cap). (#183)
- OSC 8 links: http/https open directly only with a plain host name; every other link asks first and shows the full target. Overlong or disguised targets (control, bidi or invisible characters, also percent-encoded), script schemes, abused Windows protocol handlers (including the Office handlers), and `file:` links to anything but local drive paths are never opened. (#183)
- Network and device paths such as `\\.\GLOBALROOT\…` or `\??\UNC\…` are no longer treated as local (links, working folder from OSC 7/9;9). (#183)
- "Show in folder" no longer passes commas or quotes to Explorer; more file types (e.g. `.settingcontent-ms`, `.library-ms`, `.chm`, `.msc`), trailing dots/spaces and alternate data streams are treated as executable. (#183)
- Notification texts and session names in toasts are cleaned (control, bidi and invisible characters removed, length limited); toasts always name Paneldeck and the session. (#183)

A "New project" wizard with the choice of whether to create the default types including workflows, sprints and versions/milestones that can be switched on per project, a color mode for new tags (default, project color, random); project overview, settings and deletion with a safety timer.
- **Freely configurable ticket types, fields, statuses and workflows:** the default types are *Epic*, *User story*, *Dev task*, *Subtask* and *Defect* (in German Epic, Userstory, Dev-Aufgabe, Unteraufgabe, Fehler) with color and icon; hierarchy rules define which type may sit below which. Per type there is an editor for fields (text, rich text as Markdown, checkbox, dropdown with colored values, number with limits and unit, ticket link, terminal, version, milestone, date, date and time, multi-select/labels – with required field, default value, help text, section, order and "show on card"), a status pool per project (name, color, category To do / In progress / Done) and per type a **workflow** with a transition matrix plus required fields, conditions and automatically set values per transition. Types without a workflow have no status field. Default names (types, statuses, fields, priorities, link types, kinds of work) follow the language setting until you rename them. Deleting something that is still in use requires choosing a replacement or deliberately discarding the usages (with a counter).
- **Link types and kinds of work:** *blocks / is blocked by*, *relates to* and *duplicates / is duplicated by* are built in; you can create your own link types with a ticket, terminal, URL or git branch as the target. The **Terminal** type is a system type and cannot be deleted. The kinds of work for time tracking (default: Development, Testing, Planning, Refinement) can be set per project.
- **Templates:** the types, fields, statuses and workflows of a project can be exported as a JSON file and imported into another project; the import only creates what is missing and reports items with the same name without changing existing ones.
- **Tickets:** keys made of the project key and a running number (`PAN-12`, never reused), fields per type, parent and children with progress, flag and favorite (star), comments, links, time tracking (input like `1h 30m` or `2d`; a number alone counts as hours) and a change history that records whether the window, an agent (with session name) or an import changed something. Status changes check the workflow (transition matrix, conditions, required fields) the same way everywhere: in the window and for agents.
- **Kanban boards** in Expert mode: several boards per project with name, description, columns (also several statuses in one column), a type filter and freely chosen card fields. Cards can be dragged between columns (that is a status change with all workflow rules; if required fields are missing, a dialog opens) and reordered within a column; quick filters by text, type, favorites and flag. The source of a board is "All tickets" or a saved filter (also across projects), and "Only the active sprint" shows only the tickets of the active sprint. Moving, reordering, starring and flagging a card can be undone and redone with `Ctrl+Z` / `Ctrl+Y`. Cards also show the fields *Version*, *Milestone* and *Terminal* (ended sessions in gray).
- **Tickets in the window:** a *Tickets* tab with a list (columns key, title, type, status, priority, points; sortable, text search, filters by type and status, favorites only, flagged only), a create dialog (choose the type, parent ticket, "Create another"; `Ctrl+N`), a detail view as its own page or as a side panel next to the list (switchable, the choice is remembered), fields per type in sections with a required-field check, status changes only via allowed transitions (missing required fields are asked for in the same dialog), comments (edit, delete), links and child tickets, change history, undo/redo with `Ctrl+Z` / `Ctrl+Y`, clone (one check box per field), change the type or move to another project (with a list of the fields that are kept, dropped and added), flag and star, "Log time" (duration, kind of work, start, comment) and turning a to-do card into a ticket (one undo step: the ticket goes away and the card is open again; `Ctrl+Z` / `Ctrl+Y` also work in the Todolist overview). From a width of 900 px the list also shows a chip column with version, milestone and terminal; it scrolls to the opened or just closed ticket when its row is not fully visible. A terminal entry in the ticket jumps to the running session. Permanently deleting a ticket asks for confirmation with a 3-second safety timer. If you open a ticket from another tab (board, search, backlog, dashboard, overview) or from the Terminal Hub, "Back" (`Esc`) takes you there again.
- **Rich text fields with a "Text | Visual" switch:** Markdown with a formatting toolbar (headings, bold, italic, lists, task lists, quotes, code, tables), rendered only in Visual mode; ticket keys in the text (`PAN-12`) are clickable and open the ticket. No files or images are stored.
- **Query language** (modeled on JQL) for the ticket search: comparisons (`=`, `!=`, `~`, `!~`, `<`, `>`, `<=`, `>=`, `IN`, `NOT IN`, `IS EMPTY`), `AND`, `OR`, `NOT` and parentheses, `ORDER BY` / `SORT BY` with several fields, free text, the functions `activeSprint()`, `currentDate()` and `linkedTerminal()`, the fields `sprint` and `Release version` and your own keywords (`IS favorite`, `IS NOT blocked`, `SORT BY favorites`, defined in the keyword editor). The query bar has autocomplete (`↑↓`, `Tab`/`Enter`), a history of the last queries, error messages with position and suggestion ("did you mean …?") in English and German, and **saved filters** (per project or for all projects; also as the source of a board). It sits above the ticket list (a valid query replaces the local filters there) and in the new **Search** tab, which shows the results as a table (either only this project or all projects). A question-mark button opens a **help page** with a complete guide and examples.
- **Backlog, sprints, versions and milestones** (can be switched on per project, nothing is forced on you): a **Backlog** tab with one active sprint per project (goal, start, end, duration template, work days and holidays), tickets moved by drag & drop (several with `Ctrl`/`Shift`+click) between the backlog and sprints, totals by count or points, starting and completing a sprint (open tickets go back to the backlog or into the next sprint), burndown with ideal line and work days, sprint report and velocity across completed sprints (a sprint lasts at most 4000 days); a **Releases** tab with versions and milestones (due date, "released"/"reached", progress, order, replacement when deleting). Fields of type *Version* and *Milestone* have picker editors in the ticket. Dragging and "Move to" in the backlog can be undone and redone with `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` (not: starting, completing or deleting a sprint, or the actions in the *Releases* tab).
- **Quick actions and the quick menu:** per ticket type you can define buttons with their own name in the **Quick actions** tab (e.g. "Create Devtask"): create a ticket with preset values (optionally linked to the source ticket, with placeholders in texts), change the status (optionally with values) or start a terminal/Claude session for the ticket. The **quick menu** (key `.`, e.g. in the ticket, in the list, on the board and in the backlog) searches fields and actions, sets values directly, changes the status (only allowed transitions; if required fields are open, a small form asks for them) and runs the quick actions. The quick actions "Change status" and "Create ticket" also ask for missing required fields in such a form. In open pick lists of the quick menu, `Esc` only closes the list and `Enter` takes the entry. The quick actions of the ticket type are also available as **buttons right in the ticket** (page and side panel, below the status, in the order of the type editor; with many actions a "⋯ more" menu takes the rest): a click runs the action through the same quick menu (required-field form or title input when needed; a toast with "Undo"; session start), and invalid or blocked actions are grayed out and explain themselves in their tooltip.
- **Dashboards:** a **Dashboards** tab with freely arranged tiles on a grid (search, active sprint, burndown, counts by status/type/priority as a pie or bar chart, booked time per day or week, favorites, flagged tickets, all projects), per project or global; several dashboards with one default, an edit mode (move, resize, "Tidy up"), a click on a row opens the ticket, a click on a chart segment opens the search, export/import as JSON (the import always creates a new dashboard).
- **Export and import:** in the *Templates & backup* tab a full project backup (JSON: types, fields, workflows, boards, filters, tickets with comments, history, links and times, sprints, versions and milestones) and tickets as CSV (optionally "Excel-safe", formulas are protected – also for cells that start with a tab or carriage return) as well as the type/field templates; the import only accepts its own export format, always creates a new project (asking for a new key if the key is taken) and never changes existing data. Files over 128 MB as well as counters, numbers and ranks close to the end of the number range (`i64::MAX`) and sprint periods over 4000 days are rejected before anything is created.
- **Terminal links:** in the Terminal Hub (only with Expert mode on and at least one project) a link icon in the header of a terminal (also via the context menu entry "Link ticket …" of the terminal header and the sidebar) opens a mini search by ticket key or title (`pan-12`, `login`). The ticket key appears as a chip in the terminal header and in the sidebar (with a counter for several tickets); the command palette (`Ctrl+Shift+P`) also finds tickets. When the session is closed, the link stays as "ended" (gray) and becomes active again when the session is resumed. A click on the chip opens the ticket in the *Todo list* tab (Expert mode is switched on for this if needed); "Back" or `Esc` then returns to the Terminal Hub. Fields of type *Terminal* pick a session from a list; in the ticket a click on a running entry jumps to the session in the Terminal Hub.
- **Toasts:** short messages at the bottom right, up to five stacked, each visible for ten seconds, a click closes them. When an agent changes a ticket or a to-do card, a line appears with what it did.
- **Agent interface (MCP): 18 new tools** (33 in total), depending on the mode of the *Todo list* tab – the agent always has only the possibilities of the current mode. In every mode: `list_todos` (read). Expert mode off: `add_todo`, `set_todo_done` (control). Expert mode on: `list_projects`, `get_project`, `search_tickets`, `get_ticket`, `get_time_entries`, `list_sprints`, `get_sprint`, `list_versions` (read) as well as `create_ticket`, `update_ticket`, `transition_ticket`, `add_comment`, `log_time`, `link_ticket`, `link_terminal` (control). Instead of the simple filters, `search_tickets` also takes a query in the query language (`query`, read only; an invalid query returns `invalid_query` with position and message, a text that is too long `too_large`, and after 2 seconds `timeout`); `list_sprints`, `get_sprint` and `list_versions` return sprints (with totals and report) as well as versions and milestones with progress, and answer with `feature_disabled` when the project switch is off. The same rules apply as in the window (required fields, hierarchy, workflow); agents can never delete tickets or cards or change types, workflows and projects. If an agent calls a tool of the other mode, Paneldeck answers with the new error code `wrong_mode` and an explanation. In *Settings → Agents* a line shows which tool group currently applies.

### Changed

- The main window is now frameless with its own title bar (see above); the Terminal Hub view below it is unchanged.
- New data structure in the data folder: `paneldeck.db` (SQLite, schema version 7) with the side files `paneldeck.db-wal` and `paneldeck.db-shm` while running and the folder `backups/` (or the chosen backup folder). Existing files (`settings.json`, `state.json`, `prompts.json`, `themes/`) keep their format; `settings.json` gains the new values `backup_interval_hours`, `backup_keep`, `backup_dir` and `undo_steps` (older files load with the defaults). An older Paneldeck version cannot open `paneldeck.db` – back up the data folder before going back to 1.x.
- The request limit of the agent interface rises from 64 KB to 512 KB (a comment with 20,000 characters can be 80 KB in UTF-8). The hub now answers larger requests with the error code `too_large` instead of silently closing the connection. The response of `list_sessions` gains the additional field `note`, which marks names, folders and branches as untrusted.

## [1.0.0] - 2026-11-14

First public release. From here on, the public API (MCP interface, command line, data formats in the data folder) is binding in the sense of Semantic Versioning; earlier development states were not published.

### Added

- **Terminals** with full emulation via ConPTY: PowerShell 7, Windows PowerShell, CMD, Git Bash and WSL distributions; colors, alt screen, mouse, Unicode, color emoji, CJK and seamless box-drawing characters.
- **Organization:** sessions in projects with their own layout, groups/folders (tree view), colors, tags, filters and notes; freely splittable panes, drag & drop (including folders), detach into their own windows, git worktrees per session.
- **Claude mode** (can be turned off): status display via hooks (working / approval? / ready), notifications, token and cost estimates with a cost overview, daily and per-session budget, history with exact resume, start dialog (model, permission mode), editor for `CLAUDE.md` and Claude settings.
- **Convenience:** command palette, history search, prompt library, broadcast to several terminals, file tree, git info, pasting files and images from the clipboard, tray, transparency, Windows notifications.
- **Agent interface (MCP)** with 15 tools (`whoami`, `list_sessions`, `read_terminal`, `screenshot`, `get_usage`, `search_history`, `create_session`, `send_text`, `send_keys`, `run_command`, `wait_for_status`, `queue_prompt`, `rename_session`, `focus_session`, `close_session`): off by default, levels "Read only" and "Control", access check in the hub, call log; agents identify themselves via `whoami` and create child sessions under their own.
- **Customization:** keyboard shortcuts, custom themes (JSON), terminal font, English (default) and German.
- **Windows integration without administrator rights:** installer (per user, with license page) and portable ZIP; Explorer context menu, optional autostart, single instance; uninstalling removes the hooks and the MCP registration again. Updating over a running hub is possible.
- MIT license (`LICENSE`); the license texts of the dependencies ship with the installer and the ZIP (`THIRD_PARTY_LICENSES.txt`).

### Security

- Paneldeck makes no connections to the internet and sends no telemetry; hook and MCP traffic stays local (`127.0.0.1`, with a token).
- All `unwrap()`/`expect()` calls in the program code were replaced by error handling (the release build aborts completely on a panic); the `unsafe` blocks are justified.
- The executable contains no paths of the build machine.
